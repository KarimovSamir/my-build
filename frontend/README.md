# MyBuild — frontend

Автономное демо на Next.js 16 (App Router, static export), React 19,
Tailwind 4 и shadcn/ui. Клиент и две компании используют один локальный мир
в IndexedDB. Активный профиль хранится в sessionStorage текущей вкладки.
Backend и Supabase при просмотре не вызываются.

Обзор — в [README проекта](../README.md), проверка готового демо — в
[чек-листе](../docs/autonomous-demo-verification.md).

## Запуск из корня репозитория

```bash
npm run install:demo
npm run build:demo
npm run verify:demo
npm run preview:demo
```

Адрес: `http://127.0.0.1:4173`. `Ctrl+C` останавливает preview.
Для разработки: `npm run build:shared`, затем `npm run dev:web` (порт 3000).
`next start` несовместим с этим статическим экспортом.

`.env` не нужен. `env.example` оставлен как исторический шаблон серверной
интеграции; его переменные не включают серверный режим. `build:demo` копирует
разрешённые исходники во временную папку без `.env`, исключает старые переменные
из окружения, собирает экспорт и переносит его в `frontend/out`.
Google Fonts нужны при сборке, шрифты в готовом экспорте локальные.

## Демо-профили и хранилище

`/login/` предлагает выбрать профиль. Старые адреса регистрации, подтверждения
почты и пароля объясняют демо-режим и возвращают к выбору профиля.
При выходе данные сохраняются. «Начать заново» сбрасывает их после подтверждения.
Если IndexedDB недоступен, интерфейс предлагает повторить открытие, сбросить
данные либо продолжить во временной памяти. Повреждённые данные автоматически
не удаляются. Открытие хранилища ограничено 8 секундами, транзакция — 15 секундами.

Все данные синтетические и доступны владельцу браузера. Ограничения видимости
ролей показывают поведение продукта, но не являются настоящей авторизацией.

## Тема оформления

Светлая, тёмная и «как в системе». Класс `dark` на `<html>` выставляет
`next-themes` (`components/theme-provider.tsx`), переключатель —
`components/theme-toggle.tsx` в шапке кабинета, на лендинге и на экранах входа.
Цвета берутся только из токенов `globals.css`: захардкоженный `bg-white`
сломает тёмную тему.

Палитра — тёплая бумага и терракота из логотипа, тёмные полосы (боковое меню,
панель экранов входа, призыв и подвал лендинга) одинаковы в обеих темах.
Шрифтов три, все подключены в корневом `layout.tsx`: Manrope — текст
(`font-sans`), Literata — заголовки и названия сущностей (`font-heading`),
IBM Plex Mono — номера заказов, суммы, даты и подписи капителью (`font-mono`).
Мелкий текст держит контраст WCAG AA (4.5) в обеих темах — меняя приглушённые
токены, проверяйте его заново.

## Структура

```text
src/app/                     статические маршруты, лендинг и кабинет
src/components/demo/         экраны, провайдер данных и выбор профиля
src/components/orders/       существующие формы и карточки заказов
src/components/offers/       формы предложений
src/components/ui/           компоненты дизайн-системы
src/lib/demo/model.ts        начальные данные и проверка сохранённого мира
src/lib/demo/operations.ts   команды и применение общей state-машины
src/lib/demo/repository.ts   атомарные транзакции IndexedDB
src/lib/demo/store.ts        состояние вкладки, восстановление и временный режим
src/lib/demo/transport.ts    локальный адаптер существующих форм
src/lib/demo/files.ts        проверка содержимого и SHA-256 файлов
src/lib/demo/selectors.ts    представления данных для экранов
src/lib/api.client.ts        вход форм в локальный транспорт
src/lib/types.ts             реэкспорт типов shared
public/_headers             HTTP-политика локального preview (совместимая с Pages)
public/demo/room-plan.dxf    скачиваемый пример
```

Старые модули `api.server.ts`, Supabase и realtime сохранены как исходники
прежней интеграции и не используются в экспортированном приложении.
Proxy, серверные сессии и API-routes для просмотра демо не нужны.
Карточки открываются через `/orders/view/?id=…` и `/contractors/view/?id=…`;
неизвестный ID обрабатывается интерфейсом без запроса к серверу.

Логика форм остаётся в `lib/`, доменные правила и state-машина — в `shared/`.
После правки shared нужен `npm run build:shared`. Пользовательские файлы
записываются Blob-объектами в той же транзакции, что и сущности. Скачивание
создаёт временный Blob URL; лимиты — 10 МиБ на файл и 50 МиБ суммарно.

## Проверки из корня

```bash
npm run test -w frontend
npm run typecheck -w frontend
npm run lint -w frontend
npm run test:demo-tools
npm run build:demo
npm run verify:demo
npm run verify:demo:clean
```

Vitest проверяет логику и сбои хранения с fake-indexeddb; `.spec.tsx`
проверяют серверный рендер экранов. Они не заменяют гидратацию, реальные
события вкладок и IndexedDB браузера. Спеки входят в проверку TypeScript.

`verify:demo` сканирует готовые ресурсы и проверяет HTTP без браузера.
`verify:demo:clean` повторяет установку, сборку и HTTP-проверки без backend
и `.env`. Отчёты — `tmp/demo-audit.json` и `tmp/demo-clean-audit.json`.
Целевой хостинг — существующий Vercel: конфигурация в корневом `vercel.json`,
команда `npm run build:vercel`. Она проверяет соответствие заголовков Vercel
и локального `_headers`, затем собирает и проверяет экспорт. `next dev` работает
по своим правилам, поэтому локальную приёмку проводят на `preview:demo`.
Настройки публикации — в [инструкции](../docs/autonomous-demo-publish.md).
