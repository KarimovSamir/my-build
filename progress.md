# progress.md — журнал текущей фазы

Рабочий журнал между подсессиями **одной фазы**. Правила проекта, состояние кода и грабли — `CLAUDE.md`. План подфаз — `PLAN.md`. Требования — `MyBuild_NestJS_TZ.md`.

---

## Как этим пользоваться

**В начале подсессии:**

1. Прочитать этот файл целиком — здесь только текущая фаза, это быстро.
2. Посмотреть в `PLAN.md`, какая подфаза идёт следующей.
3. Прочитать раздел ТЗ, к которому она относится.
4. Взять **ровно одну** подфазу. Не больше.

**В конце подсессии:**

1. Дописать запись по шаблону ниже — четыре блока, ни один не пропускать.
2. Дать в чат короткий отчёт и указать: «в фазе N осталось: …» либо «фаза N завершена целиком».
3. Остановиться. Не спрашивать «делать дальше?».

**Правила для записей:**

- Новая запись добавляется **вниз**. Прежние записи этой фазы не переписывать.
- «Сделано» пишется только после проверки (`CLAUDE.md` §2). Тесты упали — так и написать, с выводом.
- Незаконченное уходит в «что дальше», а не замалчивается.
- Пишем состояние, а не историю: «сейчас работает так», а не «было А, стало Б».
- Без дат, без времени прогона тестов и без точных чисел тестов: всё это устаревает к следующей подсессии и врёт следующему агенту.

**Когда фаза закрыта целиком** (`CLAUDE.md` §9): свернуть записи в `CLAUDE.md` §6 (3–6 строк о том, что теперь есть), отступления — в §7, долгоживущие грабли — в §10, и **очистить этот файл** до шапки, шаблона и точки входа в следующую фазу. Летопись живёт в git, не здесь.

## Подфазы 7.2 и 7.3 — полировка интерфейса и прод-готовность

**Сделано (7.2)**

- `app/not-found.tsx` — своя страница 404 на несуществующий адрес. До этого любой промах по адресу отдавал служебную страницу Next.js по-английски и без темы. Сессия там не читается намеренно (причина — в комментарии файла): граница `not-found` вкладывается в каждый маршрут, и обращение к cookie делало динамическими лендинг, регистрацию и восстановление пароля. Кнопка ведёт на `/`, а лендинг сам уводит вошедшего в его кабинет.
- `loading.tsx` у обеих карточек — `/orders/[id]` и `/contractors/[id]` — на общем `components/detail-skeleton.tsx` (заголовок с кнопкой + сетка «основное слева, врезка справа», число блоков задаёт вызывающий).
- **Скелетоны в тёмной теме были невидимы вовсе.** В пресете Nova токены `--muted` и `--card` в тёмной теме — один и тот же цвет, а `Skeleton` из поставки shadcn залит `bg-muted`: внутри карточки заглушка сливалась с фоном. Цвет заменён на `bg-foreground/10` — заметен на любой подложке в обеих темах. Касалось и списочных скелетонов с Фазы 3.
- Предупреждение `next/image` в dev закрыто: логотип не квадратный (файл 1125 × 773), а в пропсах стояло `width = height`. Ширина теперь считается из пропорций файла (`LOGO_RATIO` в `logo.tsx`).
- Полоса прокрутки горизонтальных лент (вкладки статусов, таблицы) — утилита `scrollbar-slim` в `globals.css`. В Windows системная полоса рисуется поверх и занимает место: под вкладками статусов это выглядело толстой серой чертой во всю ширину карточки. Прятать совсем не стали — иначе на десктопе ничто не скажет, что вкладки продолжаются вправо.

**Сделано (7.3)**

- `app.set('trust proxy', 1)` — только при `NODE_ENV=production` (`bootstrap.ts`). Без прокси доверие к `X-Forwarded-For` само было бы дырой в ограничителе частоты.
- `common/request-logger.ts` — строка в лог на каждый запрос: метод, путь, статус, время, пользователь. Middleware, а не интерсептор: отказы guard'ов (401/403/429) до интерсептора не доходят, а именно они раньше не оставляли следа. Строка запроса не логируется (в `?q=` лежит то, что искал пользователь), `/health` уходит в `debug`, чтобы пингер не забивал лог. Покрыт `request-logger.spec.ts`.
- `scripts/check-security.ts` + `npm run security:check -w backend` — проверка двух требований ТЗ §6, которые живут в самой Supabase, а не в коде: RLS на всех таблицах `public` без единой политики и приватный бакет. Прогнано на живой базе: девять таблиц, у всех RLS включён и политик ноль; бакет `order-files` приватный.
- `env.example` обоих пакетов приведены к прод-виду: что `NODE_ENV=production` включает доверие прокси, что `PORT` площадки задают сами, что `CORS_ORIGINS` на проде — домен фронта, а `NEXT_PUBLIC_API_URL`/`NEXT_PUBLIC_WS_URL` — домен backend по https и он же должен стоять в `CORS_ORIGINS`.
- Ревизия §6 по пунктам: helmet, CORS-allowlist из окружения, свой `ThrottleGuard`, глобальные guard'ы, единый формат ошибок с логом 500, валидация окружения на старте, `.env` вне git, во фронте четыре публичные переменные и ни одного секрета.

**Чем проверено**

- `typecheck`, `lint`, `npm test` (три пакета) и `npm run test:e2e` — зелёные после правок.
- Прод-режим локально: `npm run build` обоих пакетов, `NODE_ENV=production node dist/main.js` и `next start` — поднимаются, работают, консоль браузера чистая.
- В браузере под клиентом и компанией (два изолированных окна, обе темы): 404 по случайному адресу, скелетоны обеих карточек под троттлингом Slow 3G, списки, карточка заказа, каталог и карточка подрядчика, документы, уведомления, настройки, форма создания заказа, кабинет компании. Мобильная ширина — эмуляцией 390×844: горизонтального переполнения нет ни на списках, ни на карточке заказа. Фокус клавиатурой виден.
- Предупреждение `next/image` проверено в dev-режиме до и после правки: было — пропало.

**Принятые решения**

- 7.2 и 7.3 сделаны одной подсессией — явное указание пользователя.
- §8.2 закрыт решением пользователя: письма остаются штатными английскими шаблонами Supabase, HIBP пропускаем. В README это уйдёт как известное ограничение демо.
- Цвет скелета правился в `ui/skeleton.tsx`, а не в токенах темы: `--muted` используется под hover'ы и шапки таблиц, и его сдвиг поменял бы половину интерфейса ради одного случая.

**Что дальше**

- Подфаза **7.4** — деплой и README. Там же закрывается §8.1 (усыпление free-тарифа).
- По §8.1 пользователю уже сказано: интервал «раз в 6 дней» закрывает только Supabase, а backend на free-тарифе Render засыпает через 15 минут. Нужен внешний монитор на `GET /health` каждые 5–10 минут — маршрут публичный и делает настоящий `SELECT 1`, то есть будит оба конца разом. GitHub Actions cron как единственный механизм не годится: расписание выполняется с задержками, а сам workflow отключается после 60 дней без активности в репозитории. Решение пользователем ещё не названо — из §8 запись не убирать.

**Где грабли**

- **Чтение cookie в `app/not-found.tsx` делает динамическими все статические страницы.** Границу `not-found` Next.js вкладывает в каждый маршрут, поэтому `getSessionClaims()` там стоил пререндера лендингу, `/register` и `/forgot-password`. Видно только по таблице маршрутов в конце `next build`: `○` меняются на `ƒ`.
- **`--muted` и `--card` в тёмной теме совпадают.** Любая заглушка или подложка на `bg-muted` внутри карточки в тёмной теме невидима. Проверять новые такие места не глазами по светлой теме, а сравнением токенов.
- **Предупреждение `next/image` про «width or height modified» означает непропорциональные пропсы**, а не отсутствие `w-auto`: Next сверяет объявленные `width`/`height` с отрисованным размером. Классы Tailwind на это не влияют.
- **`getInstance()` у HTTP-адаптера Nest не дженерик** — `getInstance<Express>()` не собирается, нужно приведение результата.
- **Рабочий каталог инструмента PowerShell переживает вызовы** (уже записано в `CLAUDE.md` §10) — после прогона тестов из `backend` следующий `npm run build` из корня ушёл бы в тот же пакет.
